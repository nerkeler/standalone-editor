# Standalone Editor 下一轮产品化实施计划

准备日期：2026-09-26。审阅基线：本地 `main` 的 `b8370fe`。这是下一轮的工作交接文档；开始实施前重新核对 HEAD、工作区、服务状态与现有测试，不能把本次静态审阅当作运行验收。

## 目标与边界

把源码保护提示、表格、图片和工作台视觉做成一致、可靠、可长期使用的编辑体验。保持普通 Markdown 文件与相对图片路径可移植；保留文件 revision 冲突检测、历史版本、草稿恢复和三秒自动保存。所有文件操作测试使用隔离临时工作区，不对真实笔记执行迁移测试。

**完成定义：** 用户能看出源码中哪些片段无法安全进入富文本；可安全修正的内容在打开时只转换并保存一次；表格可选行列并在插入后增删；图片可插入到文档同级的 `assets/`，可调显示大小和左/中对齐，重开后保持；五处视觉微调经多轮明暗主题、桌面与窄屏审阅，不产生保存或交互回归。

## 已核对的实现事实

- `frontend/src/pages/markdownSourcePolicy.js` 只返回保护原因，不返回源码范围。`Editor.jsx` 在打开时选择源码模式，风险弹窗只在用户主动切换富文本时出现。
- 源码编辑器目前是 `<textarea>`（`Editor.jsx` 约 2497 行），无法给局部文本绘制波浪下划线。
- 表格插件已注册，但桌面和移动端都只插入固定 3×3。富文本表格序列化把所有对齐符写成 `---`，因此表格对齐仍须保护。
- 桌面图片上传按钮与隐藏文件输入框没有有效点击连接；移动端使用 `getElementById('img-up')`。上传路径固定为工作区根目录 `assets`，后端只为这个目录自动创建。
- 已有 `MarkdownImage` 自定义属性、相对图片路径解析与媒体接口。图片缩放通过 DOM `data-zoom` 和 `<!-- zoom:N -->` 注释补写；这不是完整的尺寸、对齐文档模型。
- 产品方向已写在 `PRODUCT.md` / `DESIGN.md`：安静的本地文档工作台，正文优先，清晰状态，避免装饰堆叠。

## 实施顺序

### 0. 固定基线与设计约束

1. 检查工作树、HEAD、已有变更；用隔离工作区复现桌面图片按钮无响应、3×3 表格限制、源码保护位置提示缺失。
2. 建立按语法类型拆开的测试样本：YAML、WikiLinks、嵌套列表、引用式链接、脚注、转义、表格对齐、原始 HTML、围栏附加信息；另建富文本安全样本。每类独立断言，避免一个 front matter 把整份样本直接导入源码模式后掩盖其他问题。
3. 记录现有明暗主题在 1440、1195、768、390 px 的截图作为视觉基线。当前本地 `5558` 未响应；实施时先重新检查或启动服务。

### 1. 源码模式诊断与安全自动修正

1. 将源码模式专用的 `<textarea>` 换为 CodeMirror 6 或同级可维护方案。优先使用诊断范围装饰，给**不能无损转换的具体语法片段**加低干扰的波浪下划线；悬停和键盘聚焦可读到原因、影响与建议。不要把兼容性提示伪装成 Markdown 语法错误。提供“下一个受保护位置”和可读的总数；明暗主题都可辨识，不能只靠颜色。
2. 把检测从“原因集合”扩展为共享分析结果：`reason`、准确 `from/to`、说明、是否存在已验证修正。排除代码块及行内代码中的伪匹配，支持编辑后增量或防抖更新。`requiresSourceMode` 由同一分析结果派生，避免标注与模式决策不一致。
3. 自动修正仅针对已有明确转换规则、通过往返测试的安全子集。打开干净文档后先生成候选内容，再验证语义和全部受保护信息仍在；仅当候选确实变化、当前无未保存草稿/冲突、workspace identity 和磁盘 revision 未变化时，使用现有 CAS 保存，保留历史。重开同一文档不得再次改写。未通过验证的内容原样留在源码模式并继续标注，绝不“清除警告”后覆盖原文。
4. 如果目标是让某类语法真正进入富文本，应先补齐解析、编辑器属性与 Markdown 序列化，再把该类从保护名单移除。YAML、WikiLinks、脚注、原始 HTML 与代码围栏附加信息不能通过简单格式化假装已支持。

### 2. 表格插入与编辑

1. 插入按钮打开可预览的行列选择器：常用尺寸用网格选择，同时提供数字输入；明确显示“X 行 × Y 列”、表头行选项与上限。桌面和移动端共用同一行为。
2. 光标进入表格时显示紧凑上下文工具：上/下增行、左/右增列、删行、删列、删表；不可执行的操作禁用，保留键盘与屏幕阅读器标签。使用现有 Tiptap 2 表格命令，不为这一项升级整个编辑器。
3. 验证插入、增删、撤销/重做、切换标签、自动保存和重开后的 Markdown 表格。Markdown pipe table 不支持合并单元格，因此本轮不暴露会造成不可逆序列化的合并操作；带对齐的旧表格仍保持源码保护，直到真正支持对齐往返。

### 3. 图片插入、目录、大小与对齐

1. 用唯一的 file input ref 接通桌面/移动端图片按钮；验证实际打开系统文件选择器、取消、上传失败、重复文件名和切换标签时的反馈，避免“上传成功”误报为“已插入”。
2. 以当前 Markdown 文档为上下文，后端在其**同级**创建或复用 `assets/`：`docs/note.md -> docs/assets/photo.png`；根目录 `note.md -> assets/photo.png`。沿用路径边界、符号链接拒绝、文件类型和重名保护。磁盘 Markdown 保持 `assets/photo.png` 一类相对引用，内部 API URL 只用于渲染。
3. 选中图片显示紧凑编辑工具：左对齐/居中、显示宽度预设与可键盘操作的尺寸控制；拖动角柄调整时维持长宽比并限制合理范围。控制的是文档内显示尺寸，不改原图片字节。桌面和移动端至少都能用预设及对齐操作。
4. 将尺寸和对齐保存为可解析、可往返的编辑器自有元数据，同时保持标准 `![alt](relative/path)` 图片引用；建议沿用严格限定的相邻注释方案，兼容现有 `<!-- zoom:N -->`。解析和序列化应针对图片节点，避免全局正则误匹配相同图片路径、多图、标题、括号或转义字符。旧注释无损读取，不被新的尺寸范围静默截断。重开及富文本/源码切换后属性不变，其他 Markdown 阅读器仍能显示图片。

### 4. 五项视觉精修，做三轮审阅

1. 文件树：拖拽手柄默认隐藏；行悬停、拖拽和键盘聚焦时显示；保留固定占位避免文字横跳；触屏仍有可发现的移动入口。
2. 保存区：底部蓝色主按钮降为低强调操作，保存状态始终清楚；失败、冲突及重试仍足够醒目，不能只以颜色表示。
3. 标签：提高 active tab 的文字/底线/背景层级，降低 inactive 的视觉重量；保留脏状态、错误、焦点和窄屏滚动可辨识。
4. 工具栏：统一 32–34 px 控件、图标视觉尺寸、间距及分组；表格和图片新控件沿用同一系统。
5. 正文：统一标题、段落、列表、表格的纵向节奏；清理 `Editor.jsx` 内联 `<style>` 与 `Editor.css` 的重复定义，分别检查阅读和编辑状态。

审阅节奏：功能完成后的第一轮全屏截图，第二轮明暗主题和四种宽度逐项对照，第三轮实际操作与键盘/触屏检查。每轮记录具体偏差并修正，再截图复核；避免添加新圆角、阴影、渐变或卡片来掩盖层级问题。

## 验收矩阵

- **内容安全：** 各受保护语法标注准确；源码编辑不改未触碰字节；安全修正只写一次；磁盘外部修改或草稿冲突阻止自动写；历史可恢复。
- **表格：** 自选尺寸与上下文增删在桌面/移动端可用；保存重开、撤销、表格内选区与未支持对齐语法不丢内容。
- **图片：** 按钮、粘贴、上传路径、重名与错误提示均验收；大小/对齐持久化；相对路径与旧 zoom 注释兼容，文件移动后现有相对路径维护不退化。
- **视觉与无障碍：** 明暗主题、4 个宽度、hover/focus/touch、文本对比和保存/冲突状态逐项审阅；正文始终为视觉中心。
- **工程检查：** 在 `backend/` 执行 `npm test`；在 `frontend/` 执行 `npm run test:unit`、`npm run build`、`npm run test:browser`；相关浏览器用例在 CI 实际执行。只在失败或新增变更后扩大重复验证。
