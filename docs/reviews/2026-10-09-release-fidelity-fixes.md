## 修复结果

| 编号 | 实现与验收 |
| --- | --- |
| N01 | 诊断与已安装 TipTap Link 的 URI 校验共用规则。`file://`、`obsidian://`、未知协议及危险协议的具体链接片段进入源码保护，保留目标，不扩大可执行协议范围。HTTPS、相对链接、mailto 继续富文本编辑。覆盖列表、引用、表格、重复链接，以及 CRLF 的精确位置。 |
| N02 | 源码会话保留统一 LF / CRLF，保存、同步比较、图片插入和超限回退使用一致序列化；大纲将原始字符串位置映射到 CodeMirror 内部位置。覆盖真实 Enter、LF 多行粘贴/输入、自动和手动保存、重开、撤销和重做，以及恰好 5 MiB 的中文 CRLF 文件。 |
| N03 | 上传先写同目录隐藏暂存文件，核对完整字节、同步并关闭，再用硬链接排他发布。发布后检查父目录、两条路径身份与内容。清理依据 BigInt 文件身份、快照和内容，无法证明归属时保留数据。写入/同步失败可同名重试，并发同名目标及发布后的外部改写不会被误删。 |

N01 的回归先在旧实现上复现目标丢失；N02 的回归先复现 CRLF 变为 LF。主代理的生产探针也记录了修复前失败：93 字节样本变为 87 字节，6 个 CRLF 消失，应用协议目标丢失。新构建中同一编辑仍为 93 字节、6 个 CRLF；7 类链接全部保留，重复引用中的 CRLF 链接也逐字节保留。

N03 的独立实际 HTTP 探针确认：注入 ENOSPC / EIO / sync 失败后最终名称不存在，同名重试成功且字节一致；并发同名文件保留并返回 409。发布后同长度外部改写返回 500，外部字节保留，存在无法安全删除的隐藏链接时保守保留。ENOSPC / EDQUOT 返回 507，EIO 返回 500。

## 真实限制

- 源码保留统一 LF 或 CRLF。混用多种换行的文件在编辑后仍会统一为 LF，已在 README 和边界单测明确说明。
- 安全上传要求文件系统支持硬链接。不支持时返回 `UNSUPPORTED_UPLOAD_FILESYSTEM`，不会回退到可能留下残缺最终文件的写法。权限错误保留系统错误码。
- 无法确认清理安全时可能留下隐藏暂存文件，响应携带诊断信息；最终文件已经核验完整时，仅暂存清理失败返回成功及 `temporaryCleanupWarning`。
- 本轮为 macOS + Chrome 及触控视口模拟；没有原生 Windows/Safari、真实跨卷、NAS、断电或物理磁盘满验收。EIO/ENOSPC 是故障注入。外部任意并发写入仍受现有最后检查到文件操作之间的窄窗口约束。
- 当前改动尚未形成候选提交，没有对应 SHA 的新 CI 结果。发布前需提交后验收该提交的三平台后端与 Ubuntu 前端 CI。

所有文档、配置、恢复数据和浏览器 profile 均使用隔离临时目录，没有修改真实笔记或远端服务。
