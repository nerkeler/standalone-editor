# ZIP 导入反馈与 CI 维护验收

日期：2026-10-03。起点为 `2684737`，本次源码提交为 [`bc9036a`](https://github.com/nerkeler/standalone-editor/commit/bc9036abd18e05203d07622e9da4c3f5aa0d71b7)。GPT-6 Luna max 实施；主代理复核源码、独立隔离探针、真实截图及完整回归，另由只读代理复核清理边界和前端 CI 证据。

## 本轮修复

- ZIP 导入成功但暂存清理不完整时，服务及 API 返回 `cleanupWarnings: string[]`。路径相对工作区、统一使用 `/`、去重；正常清理返回空数组。原有安全清理、回滚及失败异常语义保持不变。
- 现有导入弹窗显示成功文件数、保留原因和实际暂存路径。提醒可关闭，长路径换行并在列表内滚动；文件选择按钮支持键盘与可见焦点。导入成功后的目录刷新失败单独提示，避免把已经落盘的导入误报为失败。
- 导入响应检查组件生命周期及工作区身份。切换工作区后，旧请求不能重新打开弹窗、发布成功提示或改变新工作区的导入状态。
- 后端 CI 增加 `macos-15`，浏览器仍在 Ubuntu 执行。`checkout`、`setup-node`、`upload-artifact` 升至声明 Node.js 24 runtime 的 v6。应用和测试仍使用 Node.js `22.22.3`，支持范围仍为 `>=22.17.0 <23.0.0`。依据见[依赖维护记录](../dependency-maintenance.md)。

- 当前仍按已接受的本机/可信局域网、无登录模式运行。Origin 与工作区版本不能替代认证；本轮未加入认证，也未改变来源策略。

- `Editor.jsx` 的文档会话拆分及历史 Git 二进制资产治理后续单独处理。

- 本轮只更新代码和 GitHub，不部署或重启局域网主机，不读取或修改真实笔记；所有运行测试使用新建隔离工作区。
