# 工作目录选择改造与验收

日期：2026-10-07。基线：`main / af03af8`。GPT-6 Luna max 实施，主代理调度与验收，另有独立只读界面复核。范围仅为目录选择、工作区切换及相关回归；后端、依赖、真实笔记和局域网服务未修改。

原流程的问题是更改目录先退出编辑器，再打开选择器；导航会清空列表，弹窗随内容变化移动；路径和快捷位置的区别也不够明确。本次将欢迎页和编辑器统一接入一个目录弹窗，保留原编辑器直到切换得到验证。

## 使用流程

- 点击“更改目录”直接打开；取消保留文档、标签、草稿和目录树滚动位置。
- 顶部只有一条完整路径输入框。输入后按 Enter 或点击“打开路径”读取目录；打字本身不会发送目录请求。
- 文件夹单击进入；“上一级”和快捷位置用于导航。列表仅显示文件夹，当前快捷位置保持原位并明确标记。
- “使用此目录”才提交切换。路径未验证、读取失败或正在请求时不能确认。
- 慢请求保留上次成功的列表，说明它仍属于旧目录；弹窗和底部按钮保持位置。关闭会取消请求，旧响应不能污染下一次打开。
- 权限、目录不存在、连接失败、后端错误分别说明原因和下一步；保留可访问的完整错误详情与重试操作。

## 保存与切换边界

浏览和取消不强制保存，也不改变工作区。原有三秒自动保存继续运行。确认时先完成当前草稿保存，再请求设置目录，最后独立校验后端返回的路径、工作区 ID 和版本；它们必须同时与所选目录一致。

草稿保存失败时不发送设置请求。设置结果不确定时重新校验：只有证明旧工作区仍有效才保留旧编辑器；结果变更或无法确认则进入明确诊断状态。正常选择当前目录不会重建编辑器。

弹窗关闭后完成退出动画和焦点恢复，再释放 DOM。首轮整套回归发现旧测试把退出中的目录弹窗误认成恢复或回收站弹窗；已修正关闭生命周期及测试的可见弹窗定位，保留原有恢复内容和工作区身份断言。
