# Markdown 符号兼容性排查与修复

[返回 README](../README.md)

这份文档记录一次针对 Markdown 转换链的符号兼容性排查：链路上每一段会改写哪些符号、这次修掉了什么、以及哪些写法仍然会被规范化或保留源码。

## 转换链

```
.md 源文件
  → marked.parse            （Markdown → HTML，转义符被消费、实体被解码）
  → DOMParser 规范化        （任务列表、图片路径、图片尺寸注释）
  → TipTap / ProseMirror    （HTML → 编辑模型，不支持的节点被丢弃）
  → editor.getHTML()        （编辑模型 → HTML）
  → Turndown                （HTML → Markdown，转义与序列化规则）
  → .md 源文件
```

信息在第一步就会丢失：`\*` 和 `*` 解析成同一个文本节点，`&amp;` 和 `&` 也一样。因此“逐字节还原”不可能做到，只能定义一套**最小转义**的规范写法，并保证渲染结果不变。

## 排查方法

- **符号语料**：153 个用例，覆盖转义标点、字面标点、HTML 实体、强调/删除线、行内代码、表格、链接、自动链接、列表、标题、原始 HTML、Unicode、行首标点、连续符号。
- **真实笔记**：对工作区 44 篇 Markdown 做完整往返，统计渲染变化和新增转义符数量。
- **复现方式**：Node 侧用 domino 提供 DOM、用 TipTap 的 StarterKit schema + ProseMirror 的 DOM 解析/序列化复现编辑步骤；关键路径再用真实浏览器端到端验证。

## 修复前的发现

| 类别 | 现象 | 性质 |
|---|---|---|
| 字面 `_` `*` `[` `]` | 每个都加反斜杠：`report_id` → `report\_id`，`2 * 3` → `2 \* 3` | **过度转义**，44 篇笔记共新增 651 个反斜杠 |
| 字面 `<` `&` | `&lt;b&gt;` 往返后变成 `<b>`，被当作 HTML 加粗 | **渲染被改写** |
| 分隔线 | `---` 被改写为 `* * *` | 符号被替换 |
| 表格单元格 | 行首 `-30` 变成 `\-30`，`+ 200 units` 变成 `\+` | 过度转义 |
| 单波浪线 | `40~60%` 变成 `40\~60%` | 过度转义 |
| 反斜杠 | `\frac` 变成 `\\frac` | 过度转义 |
| 强调分隔符 | `_em_` → `*em*`，`__x__` → `**x**` | 规范化，渲染不变 |
| 删除线 | `~x~` → `~~x~~` | 规范化，渲染不变 |
| 列表缩进 | `- item` → `-   item`，`1. item` → `1.  item` | 规范化，渲染不变 |
| 硬换行 | 行尾两个空格 → `<br>` | 规范化，渲染不变 |
| HTML 实体 | `&amp;` → `&`，`&copy;` → `©` | 规范化，渲染不变 |
| 软换行 | 段内折行被合并成一行 | 规范化，渲染不变 |
| 自动链接 | `<https://…>` 被建议改写为 `[https://…](https://…)` | 源码保护 + 修复建议 |

## 修复内容

### 1. 最小转义（`frontend/src/pages/markdownCodec.js`）

新增 `escapeMarkdownText`，按 CommonMark 的分隔符 flanking 规则决定是否转义：

- 词内 `_`（`report_id`、`factor_ic_analysis`）不转义；
- 两侧是空白的 `*`（`2 * 3`、`a * b * c`）不转义；
- `[` 只有在后面可能出现 `](` / `][` 时才转义，`]` 不再无条件转义；
- `<` 后跟字母、`/`、`!`、`?` 时转义，避免字面文本变回 HTML；
- `&` 后跟实体形状（`&#?[A-Za-z0-9]+;`）时转义，避免字面实体被解码；
- 单个 `~` 不成对时不转义（`40~60%`）；
- 反斜杠只在可转义字符、换行或文本末尾前转义（`\frac` 保持原样）。

### 2. 双序列化 + 校验

每次序列化同时生成“保守版”和“最小版”，只有

```js
marked.parse(minimal) === marked.parse(safe)
```

成立时才采用最小版，否则回退到保守版。超过 200 KB 的文档直接使用保守版，避免额外的解析开销。这样即使最小转义的某条规则判断错误，也不会把错误写进磁盘。

### 3. 表格单元格按行内内容序列化

单元格里的 `-30`、`+ 200 units` 不再被当作列表标记转义；单元格没有块级结构，行首符号在这里本来就是字面量。

### 4. 分隔线固定为 `---`

`* * *`、`___`、`---` 都渲染为 `<hr>`，序列化统一输出 `---`，作者写的 `---` 不再被改写。

### 5. 行内符号与链接（第二轮）

| 问题 | 修复 |
|---|---|
| 中文锚点被 percent-encode（`#1-新浪…` → `#1-%E6%96%B0…`） | 链接目标里的非 ASCII 百分号序列在序列化时解码，`%20` 这类 ASCII 转义保持原样 |
| 单波浪线被 GFM 当作删除线（`60~120` 整段被划掉） | marked 只把 `~~` 当删除线，单个 `~` 是范围符号；转义器也只转义成对的 `~~` |
| `_强调_` 被统一成 `*强调*` | 加载时统计文档的强调分隔符（`_`/`*`、`__`/`**`），按文档风格序列化 |
| `<br>` 后面的换行被合并 | `markdownToHtml` 把 `<br>` 后的换行记为 `data-md-newline`，自定义 HardBreak 扩展带回，序列化时恢复换行（列表/引用里也不会多缩进） |

## 修复后的数据

- 44 篇真实笔记往返后新增的转义符：**651 → 21**（剩余主要是表格里可能成对的 `*` 和行内加粗里的 `1\.`）。
- 单元测试 **128 项通过**，其中新增 `tests/markdown-symbols.test.js`（18 项）覆盖本页列出的符号用例。
- 浏览器端到端测试通过：`markdown-rich-safe.browser.test.js`、`markdown-fidelity.browser.test.js`。

## 仍然会规范化的写法

这些写法的渲染结果不变，但源文件写法会被统一（信息在 Markdown → HTML 阶段已经丢失，无法逐字节还原）：

| 写法 | 统一为 | 原因 |
|---|---|---|
| `- item` / `1. item` | 按文档探测的 marker 宽度输出 | 列表风格按文档统一 |
| 行尾两个空格 | `<br>` | HTML 不记录硬换行的原始写法 |
| 段内软换行 | 合并为一行 | 渲染上等价于空格（`<br>` 后的换行已保留） |
| `&amp;` / `&copy;` | `&` / `©` | 实体在解析时已解码 |
| `<https://…>` | `[https://…](https://…)` | 打开时给出修复建议，确认后才改写 |

## 嵌套列表（2026-11 补充）

嵌套列表曾经一律进入源码模式，原因是 TipTap 会把每个列表项统一包成 `<li><p>…</p></li>`，序列化时无法区分 tight/loose，也不知道作者用的缩进。现在的处理：

- 加载时探测文档的列表风格（`listStyle.js`）：`markerWidth`（`- ` 还是 `-   `）、`step`（每层缩进 2/3/4 空格）、`safe`；
- `markdownToHtml` 给每个 `<ul>/<ol>` 写入 `data-md-loose`（tight/loose 来自 marked token），编辑器用自定义的 `MarkdownBulletList` / `MarkdownOrderedList` 扩展保留该属性；
- 序列化时按文档的 marker 宽度和缩进步长输出，并按 `data-md-loose` 决定列表项之间是否保留空行；
- 诊断只放行「缩进统一、marker 规范（`-`/`N.`）、无任务/引用/标题、无畸形标记」的嵌套列表；其余（引用内列表、制表符缩进、`*` 标记、`- - text`、任务列表、非均匀缩进）继续源码保护。

实测：`strategies.md`（2 空格 tight）、`实战版.md`（4 空格 tight）、`康复增肌…` 等可富文本往返且列表行零改写；`策略实战执行手册`（含 `- - text` 畸形标记）、`12周…`（引用内列表）、`A股市场分析`（`*` 标记）仍保留源码保护。

## 仍然保留源码保护的写法

以下内容富文本无法无损表达，打开时仍进入源码模式（`markdownDiagnostics.js`）：YAML 元数据、WikiLink、脚注、引用式链接、原始 HTML、非规范嵌套列表（见上）、混合/有序任务列表、代码围栏附加信息、嵌套容器里的表格对齐、不受支持的链接协议。

其中转义符（`\*`、`\|`、`\\` 等）是否触发保护取决于“去掉反斜杠后渲染是否改变”：会改变渲染的继续保护，不会改变的仍按源码处理（这是保守策略，避免用户主动写的转义被静默丢弃）。
